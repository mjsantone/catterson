# An assistant that learns you, and knows when to stop watching

## The steps could be saved; one person's standard could not. So I made a learning loop that turns revisions into preferences, with a pause that stops new capture without forgetting what it already learned.

A workflow can enforce steps. It cannot learn what "good" looks like for one person. A litigator and a corporate associate want different things from "summarize this," and neither will fill out a preferences form. So they start each session cold. I made a layer above the workflow: create, refine, codify, reuse, update. A correction becomes a preference the next run applies on its own. The next boundary is governance: personal taste must never outrank a firm or court rule. The hard part was never the steps. It was trust.

The strongest idea arrived in a brainstorm with a researcher: the system must never quietly take control. I had a manual "update workflow" button, then changed my mind mid-build. What if learning continued on its own, and the user could pause it instead? Pausing stops new capture while everything already learned keeps applying. In code, one state gates the capture path; the output path ignores it. The faucet is the learning; the bottle is the saved workflow. You can shut the faucet without emptying the bottle. A professional has to know exactly when the system is recording them. This draws that line in one gesture.

The applying side is measured, not asserted. An eval harness scores per-rule adherence with 95 percent confidence intervals to show where performance decays as rules stack. The learning side is the seam I am still verifying: did it capture what the person meant, not just apply the rule it saved? I would rather show that seam than call the loop finished.
